# Rules

Here are some rules you must follow:

- You have `org-docs` folder, where we will place the most important critical pieces of information, compressed analysis, ideas etc. The .md files there will be long and detailed, so reference them and use them when necessary. Write all your plans, brainstorming etc into this folder as well. DO NOT USE `superpowers` folder, write all documents produced by superpower skills into this `org-docs` folder. Each document here will be numbered, with filenames like 00001-short-summary.md. The main REQUIREMENTS.md file also lives there.
- You have `org-worklogs` folder, where you will log a brief summary of every change, every work that you have done. It will be numbered, in files like 00001-short-summary.md. Basically every agent session (or any logical piece of work done) will have a new worklog .md for it, where you will very briefly summarize and track what you have done, and what changes were made to the project. Do not edit the existing, already written, parts of worklog. Append to it new information. Start a new worklog file when necessary. Reference these worklogs when debugging or tracing previous steps.
- This project is a collection of Python scripts and some agents prompts to either analyze or run QA for SEO websites. It is designed to work on already live websites.
- Regarding VCS with Git and GitHub: after running an agent and implementing a plan, when the work has reached its logical conclusion - always commit your changes with a meaningful commit message. Use the `main` git branch for all work, unless specified otherwise.

These rules will help you be consistent and productive and transparent about your work, and will also enable some rudimentary memory.
